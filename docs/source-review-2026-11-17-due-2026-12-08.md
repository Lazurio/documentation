## Owner's decisions

Matěj Suchánek decided two points on 17 November 2026, after the first version
of this pull request asked for them. They were relayed in the working thread of
this review and are recorded here as his decisions, not as provider or Lazurio
source evidence. Both issues moved from `ISSUES.open.json` to
`ISSUES.resolved.json`.

- **The device name follows the product (`issue-2026-11-17-003`, source
  `lazurio-device-node-names`).** Since #68 `guide/tailscale-add-device` told
  the person's agent not to use `--hostname`, said that the Organization Admin
  sets the name at approval and called a `-1` suffix normal. The agent manual
  of v0.1.22 (`src/folder/manual.ts`, Adding a computer to a tailnet, steps 1
  to 5, unchanged on main) says the opposite, and the guide now follows it: on
  Windows and Mac the agent names the computer `<login>-<device>` with
  `--hostname` at its first sign-in, before approval, from the login that the
  Organization Admin sends with the address; it never changes the computer's
  own name. It reports success only after the final name and the network are
  verified. It renames with `tailscale set --hostname` only a device it has
  confirmed as newly registered and not approved, and only to correct its own
  mistake; when the device may be approved, this cannot be established or the
  name differs because of a collision (`-1`), it changes nothing and hands the
  exact state to the Organization Admin, because an approved device's name is
  part of its access (agent manual, steps 4 and 5). Pablo's review of
  `b5e00ba` asked for this guard in the copyable prompts.
  Tailscale's `login` takes `--hostname` (`cmd/tailscale/cli/up.go`, the flag
  set `login` shares, identical in v1.104.5 and v1.104.7). A phone, and a
  computer set up without an agent, keeps the name from the system for now,
  because the Tailscale apps offer no setting for it (`issue-2026-11-03-001`).
  The source moves from the GEN3 record to the agent manual at v0.1.22.
- **The GEN3 order for new connections is removed (`issue-2026-11-17-004`,
  source `lazurio-external-apps-current`).** The order official MCP server,
  official CLI, Composio, reviewed open-source tool, supervised browser, which
  LazurioPlatform leaves out of the Folder on purpose ("The Root's order for a
  new connection is left out"), and the links to the GEN3 standard as its
  source are gone from `environment-app-connections`, `data-access-security`,
  `public-evidence`, `deployment-operations`, `lazurio-vs-microsoft-copilot`
  and `it-administrators` in both locales. Where a page says how an app
  connects, it now gives LazurioPlatform's rule: every Integration has exactly
  one path, a tool from Settings → Tools, Executor or Composio, and the user
  connects it; agents never start a connection, and when an app has no path
  they say so and send its card. The forbidden list now cites decision 0162.
  The Composio prompt on `guide/tool-connections` no longer asks an agent in
  Lazurio to start the connection itself. No page needs the GEN3 source any
  more, so `lazurio-external-apps-current` leaves the map; its pages cite
  LazurioPlatform's Integrations at v0.1.22, decision 0162 and the agents'
  manual instead. Links to the same GEN3 document at other revisions stay where
  they support other statements and do not present the order: revision
  `3c5bda5` on `reference` (`lazurio-external-apps`) and revision `66e437f` on
  `provider-notes` (`lazurio-external-apps-org-steps`), both due on
  17 December 2026.
